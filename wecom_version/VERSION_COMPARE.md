# 两个版本对比说明

## 📊 版本概览

| 特性 | 版本A：JSON配置方式 | 版本B：API方式 |
|------|-------------------|---------------|
| **文件名** | `main_json.py` | `main_api.py` |
| **数据来源** | 本地JSON文件 | f1api.dev API |
| **数据更新** | 手动维护 | 自动实时获取 |
| **稳定性** | ⭐⭐⭐⭐⭐ 极高 | ⭐⭐⭐⭐ 高 |
| **数据完整性** | ⭐⭐⭐⭐⭐ 完整（手动维护） | ⭐⭐⭐⭐ 完整（API提供） |
| **依赖程度** | ⭐⭐⭐⭐⭐ 低（仅F1赛程API） | ⭐⭐⭐ 中等（需额外API） |
| **配置难度** | ⭐⭐⭐⭐⭐ 简单 | ⭐⭐⭐⭐⭐ 简单 |
| **适用场景** | 服务器长期部署 | 追求实时数据更新 |

---

## ✅ 版本A：JSON配置方式（推荐⭐）

### 优点
- ✅ **稳定性最高**：不依赖外部API，数据存储在本地
- ✅ **速度最快**：无需网络请求获取赛道数据
- ✅ **数据可控**：可以精确控制显示的数据内容
- ✅ **离线可用**：即使没有网络也能发送周一通知（只要已获取赛程）
- ✅ **维护简单**：每年只需更新一次JSON文件（新增赛道或更新记录）

### 缺点
- ⚠️ **需要手动更新**：新赛道或新纪录需要手动修改JSON文件
- ⚠️ **静态数据**：不会自动获取最新的圈速记录

### 使用方式
```bash
cd wecom_version
python main_json.py
```

### 数据结构示例
```json
{
  "suzuka": {
    "name": "铃鹿赛道",
    "name_en": "Suzuka Circuit",
    "country": "日本",
    "flag": "🇯🇵",
    "first_race": 1987,
    "lap_length_km": 5.807,
    "laps": 53,
    "race_distance_km": 307.471,
    "lap_record": {
      "time": "1:30.965",
      "driver": "基米·安东内利",
      "year": 2025
    }
  }
}
```

## ✅ 版本B：API方式

### 优点
- ✅ **自动更新**：自动获取最新的赛道数据和圈速记录
- ✅ **数据实时**：始终显示最新的官方数据
- ✅ **无需维护**：不需要手动更新JSON文件
- ✅ **减少工作量**：省去了每年更新数据的工作

### 缺点
- ⚠️ **依赖外部服务**：依赖f1api.dev的稳定性
- ⚠️ **网络延迟**：每次发送周一通知时需要请求API
- ⚠️ **API限制**：可能受到API调用频率限制
- ⚠️ **数据准确性**：依赖第三方API的数据质量

### 使用方式
```bash
cd wecom_version
python main_api.py
```

### API数据来源
- **服务**：f1api.dev
- **数据内容**：赛道长度、圈数、圈速记录、首次办赛年份等
- **更新频率**：实时更新
- **费用**：免费

## 🎯 推荐选择

### 选择版本A（JSON配置）如果：
- 🏆 **追求稳定性**：服务器长期运行，不能容忍服务中断
- 🔧 **可控性要求高**：希望完全控制显示的数据内容
- 🌐 **网络环境不稳定**：服务器可能偶尔断网
- ⏰ **不介意年度维护**：愿意每年花10分钟更新JSON文件

### 选择版本B（API方式）如果：
- 🔄 **需要实时数据**：希望始终显示最新的圈速记录
- 🆕 **不想维护数据**：不想手动更新JSON文件
- 📊 **信任第三方API**：接受依赖外部服务
- 🧪 **短期使用**：临时部署或测试使用

## 🛠️ 技术实现对比

### 版本A：JSON方式
```python
# 数据加载
with open('circuits_data.json', 'r') as f:
    circuits = json.load(f)

# 获取数据
circuit_data = circuits.get(circuit_id)

# 优点：速度快，稳定
# 缺点：静态数据
```

### 版本B：API方式
```python
# API请求
response = requests.get(f'https://f1api.dev/api/circuits/{circuit_id}')
data = response.json()

# 数据转换
circuit_data = format_circuit_data(data)

# 优点：实时数据
# 缺点：依赖网络，有延迟
```

## ❓ 常见问题

### Q: 两个版本的依赖有什么区别？

**答**：依赖完全相同！
```
requests>=2.28.0
APScheduler>=3.10.0
pytz>=2022.1
```

两个版本使用的依赖完全一样，切换版本无需重新安装。

### Q: 可以同时运行两个版本吗？

**答**：可以，但不建议。
- 会收到重复的消息
- 浪费服务器资源
- 建议选择其一

### Q: 如果选择了版本A，以后可以切换到版本B吗？

**答**：当然可以！
- 两个版本完全兼容
- 只需修改配置后重启即可
- 建议先在测试环境验证

### Q: JSON文件中的数据准确吗？

**答**：数据来源于官方F1记录，准确可靠。
- 包含2025赛季所有赛道
- 圈速记录为官方最快圈速
- 每年F1赛季开始前更新即可

### Q: API版本如果API挂了怎么办？

**答**：程序会记录错误日志，但不会崩溃。
- 周一通知会显示"未知"数据
- 其他提醒功能不受影响
- 建议监控API可用性
